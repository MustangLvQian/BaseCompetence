# 会话不关闭，历史每轮重复计费——一个会话只干一件事

**症状**：会话一直开着不关，之后每次提问账单都明显偏高。用户因此损失了不少钱才发现。

**根因**：每次向模型发消息，整个会话历史都会随请求重新发送并计费。prompt cache 命中时便宜，但缓存通常几分钟就过期；闲置过夜的会话第二天继续 = 全量历史重新计费。会话越长、闲置越久，浪费越大，且用户看不到任何报错，只会看到账单变大。

**规则**：
- 一个会话只干一件事，干完就提醒用户关闭或开新会话
- 任务之间的上下文靠 `docs/handoff.md` 传递，不靠留着旧会话
- 长时间闲置的会话不要再继续，直接开新的
- 单会话过长时主动建议压缩或拆分

**守卫**：`none`。不能自动检查，靠上面的规则人工遵守；不要把它当成已强制执行的规则。
